# Session Reports — Human/Agent Narrative Layer

## Purpose

Session reports are the **human/agent narrative layer** that links authoritative
evidence — `EvidenceRef` / `EvidenceRefs`, `manifests/*.json`, result arrays
(`results/**/*.npy`, `results/**/*.npz`), `gen2_modification_ledger.jsonl` /
`project_truth_ledger.json`, and sealed figures — into a readable, append-only
chronology.

They are **not a replacement** for any of those authorities:

| Authority | What it proves | Session report role |
|-----------|---------------|---------------------|
| `manifests/*.json` + hashes | Deterministic code/config/param/seed identity, `config_hash`/`hp_hash` | Cites, never contradicts |
| `EvidenceRef` manifests | Dataset/array provenance | Links via `EvidenceRefs` |
| `results/**` arrays | Quantitative observations | Summarizes in compact tables, points to arrays |
| `gen2_modification_ledger.jsonl` | Model-state mutation history | References ledger entries |
| `tests/` + gate scripts | Verification | Lists receipts |

If a session report contradicts an authoritative manifest or ledger, **the manifest wins**.
The validator (`validate.py`) enforces this via `config_hash` / `code_sha` checks.

## Directory Structure

```
docs/sessions/
├── README.md          # this file — rules, schema overview, index contract
├── SCHEMA.md          # JSON sidecar schema + validation rules (normative)
├── TEMPLATE.md        # empty 15-section template (copy to start a session)
├── validate.py        # validator: md sections + json sidecar + artifact + hash checks
├── INDEX.md           # auto-curated index (Session|Date|... + Frontier + Lessons + Friction)
└── 2026/
    ├── 2026-08-29_001_slug.md       # Markdown is AUTHORITATIVE
    └── 2026-08-29_001_slug.json     # JSON sidecar for retrieval (derived, not authoritative)
```

- `docs/sessions/INDEX.md` — **automatic index**, regenerated by `validate.py --reindex` and on session addition.
- `docs/sessions/2026/` — year-sharded session files. Filename convention: `YYYY-MM-DD_NNN_slug.md`
  where `NNN` is zero-padded daily sequence.

## Rules (Append-Only)

1. **Append-only, never overwrite.** Once committed, a session file (`*.md` + `*.json`) is frozen. Corrections are a new session that cites the prior session. `validate.py` warns if a tracked file's `git log` shows in-place mutation after seal.
2. **Markdown is authoritative.** In any Markdown-vs-JSON disagreement, Markdown wins. JSON is a retrieval sidecar.
3. **JSON sidecar is required** for every session Markdown. Same basename, `.json` extension. `validate.py` requires both.
4. **Evidence before interpretation.** Sections 5–6 are observations with refs/hashes; Section 7 is interpretation that must cite supporting observation IDs.
5. **No scientific code/param/manifest mutation in G (ADAPT) session-report tasks.** Session-report scaffolding must not alter `jomission/`, `manifests/*.json`, estimands, gates, or model state.
6. **Every session links visualization** when a figure exists (Section 5 / Section 6). The visual requirement is enforced by the template checklist.

## 15-Section Session Schema (Normative Overview)

Each session Markdown MUST contain these 15 sections in order (H2 headings). See `SCHEMA.md` and `TEMPLATE.md` for exact headings and tables.

| # | Section | Purpose | Key fields / table |
|---|---------|---------|-------------------|
| 1 | **Session identity** | Who/when/what code | session ID, UTC + local time, branch, HEAD / code SHA, parent model & `config_hash`/`hp_hash`, agent roles, env (Python/JAX/JaxFNE/manifest hashes) |
| 2 | **Goal** | Question + acceptance predicate BEFORE results | research question, acceptance predicate (pass/fail threshold), out-of-scope |
| 3 | **Starting authoritative state** | What is known before work | Each claim tagged `OBSERVED` / `DERIVED` / `INFERRED` / `MODEL_ASSUMPTION` / `LITERATURE_PRIOR` / `UNRESOLVED`; cite manifest/ledger/commit |
| 4 | **Work performed** | What was done | Table `Worker \| Assignment \| Action \| Artifact \| Result` — execution ≠ verification |
| 5 | **Evidence** | What was produced for verification | `EvidenceRefs`, manifests, arrays (with `sha256[:16]`), hashes, test receipts, figures, visualization reports, literature refs |
| 6 | **Observations** | Compact quantitative results | Tables only; no interpretation; each row has units, n, and artifact link |
| 7 | **Interpretation** | What observations mean | Explicit `observation ≠ interpretation`; each claim cites supporting observation IDs from §6 |
| 8 | **Negative / insufficient results** | Bounded vocabulary | `NEGATIVE_INSTANCE` / `NULL_RESULT` / `INSUFFICIENT_POWER` / `INCONCLUSIVE` / `RESOURCE_BOUNDARY` / `BLOCKED`; `FALSIFIED` reserved for L0–L5 criterion failures |
| 9 | **Unexpected findings** | Surprises outside the acceptance predicate | Observation + why unexpected + follow-up priority |
| 10 | **Tool / workflow friction** | What slowed work | Table `Friction \| Cause \| Workaround \| Permanent repair?` |
| 11 | **Learned lessons** | Durable knowledge | Table `Lesson \| Trigger \| Cause \| Repair \| Evidence \| Scope \| Confidence \| Persistence YES\|NO` |
| 12 | **Harness / tool proposals** | Concrete improvements | Type ∈ `PROJECT_RULE` / `TEST/GATE` / `JOMISSION_TOOL` / `JAXFNE_UPSTREAM` / `DOCUMENTATION` / `VISUALIZATION` / `AGENT_WORKFLOW` |
| 13 | **Scientific state transition** | How the world changed | `Before \| After \| Unlocked \| Still gated \| Invalidated \| New uncertainty` |
| 14 | **Next action** | Single highest-value next step | One primary (with rationale + ready predicate) + optional secondary |
| 15 | **Progress score** | Verified capability delta | `Current / Previous / Delta / Reason` — score reflects verified capability, not activity |

Section presence and heading spelling are validated by `validate.py`. See `SCHEMA.md` for field-level JSON rules and `TEMPLATE.md` for the copy-paste skeleton.

## Index Contract — `docs/sessions/INDEX.md`

`INDEX.md` is the **automatic, derived entry point** for humans and future agents. It is regenerated (not hand-edited) and contains:

### 1. Session table

Columns exactly:

```
Session | Date | Parent | Question | Verdict | Model Δ | Key lesson | Next
```

- `Session` — link to `2026/YYYY-MM-DD_NNN_slug.md`
- `Date` — UTC date from session ID
- `Parent` — `parent_model` (`config_hash[:8]` + manifest name)
- `Question` — §2 goal (one line)
- `Verdict` — `POSITIVE` / `NEGATIVE_INSTANCE` / `NULL_RESULT` / `INCONCLUSIVE` / `RESOURCE_BOUNDARY` / `BLOCKED` / `FALSIFIED(Ln)`
- `Model Δ` — `NO_MODEL_DELTA` or ledger entry ID (e.g., `GEN2_C020`)
- `Key lesson` — highest-confidence `Persistence=YES` lesson, or `—`
- `Next` — §14 primary next action (one line)

Rows sorted descending by session ID (newest first).

### 2. Current frontier

Synthesized from the **latest session's** §13 (`Unlocked` + `Still gated`). One paragraph + bullet list. If no sessions exist, states `No sessions yet — frontier is manifests + ledger.`

### 3. Lessons awaiting promotion

All lessons with `Persistence=YES` from sessions not yet promoted to `AGENTS.md` / project law / harness docs. Table:

```
Lesson | Source session | Scope | Confidence | Proposed target
```

Cleared when the lesson is promoted (validator cross-checks `AGENTS.md` diff if available).

### 4. Recurrent friction

Grouped by normalized friction string. Table:

```
Friction | Occurrences | Sessions | Last workaround | Permanent repair?
```

If the same friction (case-insensitive, punctuation-stripped match) appears in **≥2 sessions**, the row is flagged:

> `⚠️ HARNESS_REVIEW_REQUIRED — friction recurred ≥2 sessions; propose harness/tool fix in next session §12.`

### Other index requirements

- **Retrieval rule for future agents** (printed at top of `INDEX.md`):
  > `Retrieval: read authoritative manifests + INDEX.md + relevant session Markdown(s). Mutable current state (latest manifest/ledger/HEAD) overrides historical session narrative. Never treat a session as authority over a manifest.`
- **Visual requirement:** Every session row that has a figure artifact (§5) must link the visualization in the `Session` cell tooltip or an adjacent `Viz` link. `INDEX.md` generation warns if a session lists figures but none are linked.

## Usage

```bash
# start a new session
cp docs/sessions/TEMPLATE.md docs/sessions/2026/2026-08-29_001_my-question.md
cp docs/sessions/TEMPLATE.md.json docs/sessions/2026/2026-08-29_001_my-question.json  # or create sidecar per SCHEMA.md
# ... fill both ...

# validate single session (markdown path; sidecar inferred as .json)
python docs/sessions/validate.py docs/sessions/2026/2026-08-29_001_my-question.md

# reindex after adding sessions
python docs/sessions/validate.py --reindex
python docs/sessions/validate.py --reindex --strict   # fail on recurrent friction without §12 proposal

# validate all sessions
python docs/sessions/validate.py --all
```

## Authority Precedence

```
manifests/*.json  >  gen2_modification_ledger.jsonl  >  results/** arrays  >  session Markdown  >  session JSON sidecar  >  INDEX.md
```

`INDEX.md` and JSON sidecars are **derived** and never authoritative.
